Guide

Everything you need for everyday work with Copse. If you know git, most of it will look familiar; the differences are noted as they come up.

Getting started

Start a new repository in the current folder, or clone one from any git server or another Copse repository:

copse init
copse clone https://github.com/you/project.git

Copse keeps its history in a .copse folder. Your name and email come from copse config user.name and user.email, or from git's settings if you have them.

Committing

There's no staging area. status shows what changed, and commit takes all of it:

copse status
copse commit -m "Fix the login page"

To commit only some files, name them; everything else stays uncommitted:

copse commit -m "Update the docs" docs/ README.md

Forgot something? copse commit --amend replaces the last commit with your current files, keeping its message unless you give a new one.

Picking changes

copse commit -p goes through your changes one at a time and asks about each: y to commit it, n to leave it, s to split it into smaller pieces, e to edit it, q to stop. Your files aren't touched; whatever you don't pick stays as an uncommitted change.

In the interactive screen, enter on a file does the same, and lets you pick single lines.

Looking at history

copse log --oneline --graph     # the history, with branches drawn
copse show                      # the latest commit and what it changed
copse diff                      # your uncommitted changes
copse show HEAD~2:src/app.rs    # a file as it was two commits ago

log takes git's --format and --pretty options, and copse blame shows who last changed each line.

Branches and merging

copse branch feature        # make a branch
copse checkout feature      # switch to it
copse checkout main
copse merge feature         # bring its work into main

Merges follow renamed files and moved folders the way git does. If both sides changed the same lines, Copse marks the conflict in the file; fix it and run copse commit, or give up with copse merge --abort.

copse branch -d feature deletes a branch once its work is merged, and tells you how to bring it back.

Rebasing

copse rebase main replays your branch's commits on top of main. With -i you choose what happens to each commit: reorder, reword, squash, edit or drop. After a conflict, fix it and run copse rebase --continue.

copse cherry-pick copies single commits onto the current branch, and copse revert adds a commit that undoes one.

Undo

Copse records every move your branch makes. copse undo reverses the last one, whether it was a commit, merge, rebase, reset or checkout. Run it again to redo.

copse undo
copse reflog                # every recorded move, newest first

Anything that would throw work away keeps a backup first. copse restore file.txt discards your changes to a file, and copse reset --hard moves the branch, but both stash your uncommitted work before they do.

Putting work aside

copse stash                 # put your changes aside
copse stash list
copse stash pop             # bring them back

A stash can be brought back after you've made new commits, or on another branch: it's a handy way to move unfinished work.

Remotes and GitHub

Copse works directly with GitHub, GitLab, Codeberg and any git server, over HTTPS or SSH. To your teammates it looks like any other git client.

copse remote add origin git@github.com:you/project.git
copse push                  # send your work
copse pull                  # get what others pushed
copse pull --rebase         # or put your commits on top of theirs

Signing in uses git's saved logins, or your SSH key. For GitHub over HTTPS, the password is a personal access token. Tags, signed commits, submodules and Git LFS all work, and so do shallow (--depth) and partial (--filter=blob:none) clones.

The interactive screen

Run copse on its own for a full-screen view with four tabs:

ScreenWhat you can do
1 ChangesPick files or single lines, commit, discard, stash
2 HistoryBrowse the commit graph; check out, revert, cherry-pick
3 BranchesSwitch, create, delete and merge branches
4 UndoStep back to any earlier point

F, L and P fetch, pull and push in the background, and ? shows every key.

Working with git

Everything Copse pushes is ordinary git: commits keep their git ids, so history stays identical on the server. If you use an editor or tool that reads .git directly, copse git-view on keeps a read-only .git view up to date for it.

Everything else

Worktrees, sparse checkouts, hooks, aliases, bisect, plumbing commands, the storage format and how Copse is tested are all in the full reference. copse help and copse COMMAND --help list every option.
